# Security and feature review

Review date: 2026-10-19. The fixes are based on the current `main` branch, including the subtitle changes in PR #11.

## Scope and approach

Reviewed the Electron main/preload boundary, navigation and content policy, file writes and project sidecars, autosave/recovery, image import and caches, Story model/editor/layouts, Collage and Borders exports, video/ffmpeg and music analysis, timeline timing/playback, dependency lockfile, developer scripts, and build/release workflow. Compared behavior with the README and existing tests, then added focused regressions for verified failures. This is a source review and local execution of the automated suites; it is not a native macOS/Windows penetration test or an audit of Chromium/ffmpeg internals.

The application has no server or account system. Its principal trust boundaries are imported project/media files, the sandboxed renderer, the privileged Electron main process, native media tools, and packaging dependencies.

## Findings and fixes

| Finding | Impact and trigger | Resolution | Regression coverage |
| --- | --- | --- | --- |
| Privileged IPC did not authenticate its sender | Another renderer reaching the preload channels could request filesystem, export, or autosave operations. The close-time flush acknowledgment also accepted any sender. This was a missing boundary check, not evidence of a demonstrated remote compromise. | Require the active window's exact main frame and application document for every invoke/message and flush acknowledgment. | `security.test.ts`; a real second Electron renderer is denied file IPC in `security-review.spec.ts`. |
| Development navigation used a string prefix; production scripts allowed inline execution | A URL prefix does not identify an origin/document. The production content policy unnecessarily allowed inline JavaScript and localhost connections. | Compare parsed document URLs, allow fragment changes only, require a loopback HTTP development server, ignore its environment override in packaged apps, deny unrelated navigation/redirects and webviews, and deny unneeded permissions. Remove inline-script/localhost allowances from production; retain React refresh allowances only in Vite development. | Deceptive URL cases and sender/frame cases in `security.test.ts`; inline script rejection and normal app startup in Electron. |
| ffmpeg could interpret video music paths as protocols and follow nested network inputs | A crafted project music URL could be handed to the native encoder. A local playlist can also contain remote references. | Accept absolute filesystem paths for video music, explicitly use the `file:` protocol, and restrict every ffmpeg media input to `file,pipe`, including analysis inputs. Validate optional loop lengths. | Local/protocol input cases and real encode/decode tests in `video.test.ts` and `beats.test.ts`. |
| Project deserialization copied unchecked element/video properties | Objects in fields such as `frameColor` or text size could crash the inspector or renderer; duplicate/reserved IDs could misdirect edits and dictionary lookups. | Construct typed records from allowed fields, validate positive dimensions and numeric styles, normalize video options, reject invalid/duplicate IDs and invalid spread indices, and drop protocol music references. Resolve relative music paths beside the project, like photos. | `project-validation.test.ts`, existing project round trips and editor tests. |
| Unbounded saved music offset | Extremely large finite offsets lose integer precision in beat-clock iteration and can freeze the renderer. | Bound loaded and edited offsets to the supported 25-minute analysis range; normalize nonfinite edits. | An extreme-offset project is loaded and its beat-synced timeline computed in `project-validation.test.ts`. |
| Timed-out autosaves could commit stale work later | A delayed photo read could send an old IPC save after a newer save. A main-process write abandoned by `Promise.race` could later replace the current project or resurrect cleared work. | Check abandonment before sending IPC; abort timed-out main-process writes and check the signal before publishing temporary files or committing sidecar bookkeeping. Keep recursive clears serialized until they actually finish. | Delayed reads/writes, timeout recovery, latest-state preservation and clearing in `autosave-writer.test.ts` and `autosave-queue.test.ts`. |
| Freshly generated stories could be lost on immediate close | Generation marked the initial story clean, so closing before the two-second autosave debounce skipped the flush. | Treat generated work as dirty until saved/opened, allowing the normal close-time flush to preserve it. | Immediate close after generation in `security-review.spec.ts`. |
| Deleting the final page left an older autosave | Empty stories were always skipped, so the removed pages returned on recovery. | Save empty states after a story has existed, while preserving the startup recovery copy until the user begins working. | `autosave-writer.test.ts`; existing recovery scenarios. |
| Reusing sidecar names overwrote photo bytes belonging to older saves | Saving a different pasted image with the same name into the same Photos folder could change an older project snapshot before its replacement JSON was committed. | Reuse identical bytes, allocate a fresh name for different bytes, and publish with exclusive writes. | Repeated saves with colliding names in `project-sidecar.test.ts`. |
| Page context-menu duplicate/delete targeted the selected page | Right-clicking a different thumbnail did not update the editor's ref synchronously; the action read the old selection. | Pass the clicked page index explicitly and keep toolbar button events out of the optional index argument. | Duplicate and delete on unselected pages in `security-review.spec.ts`; existing page-management tests. |
| Video cancellation had gaps around cache lookup/save dialogs and final publication | Cancellation during cache preparation or a native save dialog could still start encoding/copying. A cancellation at encode completion could still replace the destination. | Check abort state after lookup; track the whole main-process request, including the dialog and cache copy; cancel it regardless of the renderer's encoding phase; check cancellation before the final rename. | Deferred save-dialog cancellation in Electron; cancellation at encode completion in `video.test.ts`. |
| Video temporary output had a predictable name | An unrelated file or symlink at `.<output>.partial.mp4` could be overwritten by ffmpeg. | Encode inside a unique private directory on the destination filesystem, then rename the completed video and clean up the directory. | Real encoding preserves a sentinel at the former predictable path in `video.test.ts`. |
| Packaging dependency advisory | npm reported eight moderate entries, all tracing to the `sprintf-js` denial-of-service advisory GHSA-hp3w-g68c-fv3c through `roarr`/`global-agent`. These are development/packaging dependencies. | Override `global-agent` with compatible version 4.1.3, which removes that logging dependency chain; update the lockfile. | Full npm audit now reports zero vulnerabilities; packaging proxy bootstrap compatibility checked locally. |
| UI regressions were absent from CI | The workflow built installers and ran unit tests, but did not run Electron end-to-end checks. Its default token permissions depended on repository settings. | Add the complete Electron suite on Linux/Xvfb, require it before release publication, and default workflow permissions to `contents: read` with the existing explicit release write grant. Fix the timeline test's assumption that every display permits a 50 px/s zoom value. | Local full Electron suite; platform packaging and the new workflow are checked by GitHub Actions. |

## Validation

- Baseline: 1,782 unit tests passed and one macOS-only VideoToolbox test skipped; typecheck and production build passed.
- Updated unit, typecheck, production build, Electron end-to-end and npm advisory results are recorded in the PR description.
- Electron scenarios cover launch/tab switching, import, image preview and undo, both Collage modes, Borders finishes, Story layouts/crops/titles/subtitles, hiding and page management, image/video export, autosave/recovery, recent projects, beat sync, timeline edits and cache reuse, plus the new security/data-loss regressions.

## Remaining constraints

- macOS VideoToolbox, HEIC/TIFF conversion, signing, and Windows installer behavior require their native runners. They cannot be established by Linux tests; the existing macOS/Windows build jobs remain responsible for platform checks.
- The trusted application renderer still has broad local-file capabilities by design. Sender checks and CSP reduce exposure but do not make a compromised trusted renderer harmless. Native media parsers remain an external attack surface and require timely upstream updates.
- Distribution remains unsigned/ad-hoc signed as documented by the project. Trusted signing/notarization credentials and release policy are outside this code change. Build scripts fetch third-party executable artifacts over HTTPS; their upstream contents were not independently audited here.
- Zero npm advisories means no findings in the registry's current advisory database, not proof that every dependency is vulnerability-free.
